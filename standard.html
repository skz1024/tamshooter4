1. 게임 규격

  • 장르: 2D 슛뎀업 (Shoot 'em up)
  • 해상도: 800x600
  • FPS: 60 고정형
  • 엔진: tamsaEngine (자체 제작)
  • 프로그래밍 언어: javascript
  • 개발 환경: VS Code + ts-check

2. 유저 스탯 목록

  • attack 공격력: 플레이어의 DPS
  • shield 실드: 적의 공격을 받으면 체력보다 먼저 감소
  • shield recovery 실드 회복: 일정량을 모으면 실드를 1 회복한다.
  • hp 체력: 실드가 받을 수 있는 데미지 보다 크면 감소한다.
  • exp 라운드를 진행하면서 얻는 경험치
  • lv 레벨: 컨텐츠 제한 용도로 사용
  • gold 골드: 라운드를 진행하면서 얻는 자원
  • Damage Reduction Rate 데미지 감소 비율: 예약된 스탯, 현재는 사용 안함
  • defense 방어력: 사용 불가, 더미 데이터

3. 스탯의 처리 규칙

  • 공격력
    1. 무기는 공격력의 16%, 스킬은 공격력의 21%의 비율로 공격한다.
    2. 스킬은 총 4종류를 동시 사용할 수 있으므로 이론상 dps는 무기와 스킬을 다 합쳐서 100%로 간주한다.
    3. 가변 공격력을 만들 수 있는 크리티컬, 범위 공격력 같은 요소는 금지한다.
  • 체력, 실드, 실드회복
    1. 피해를 받으면 실드(shield)가 먼저 감소한다.
    2. 실드가 피해량을 전부 감당하지 못하면, 남은 피해량만큼 체력(hp)이 감소한다.
    3. 체력이 실드보다 먼저 감소하는 경우는 없다.
    4. 체력(hp)이 0이 되면 게임 오버가 발생한다.
    5. 실드 회복의 기본 값은 100/6000이며 매 프레임 마다 상승한다.
    6. 게임의 FPS가 60이므로 기본값 기준 1초에 1씩 실드를 회복한다.
    7. 실드 회복은 0.5초보다 더 짧은 간격으로 회복되지 않는다. (예약됨)

4. 라운드

  • 라운드 입장 조건
    1. 정해진 레벨과 기준 값 이상의 공격력이 필요하다.
    2. 제한 수치는 라운드에 커서를 갖다 대면 알 수 있다.
    3. 레벨 또는 공격력이 정해진 값 보다 부족하면 입장 할 수 없다.
  • 라운드 종료 규칙
    1. 클리어 조건: 진행 시간이 정해진 값 이상이고 플레이어가 생존해 있을 때, 이 때는 클리어 보너스 경험치를 얻는다.
    2. 게임오버 조건: 플레이어의 체력이 0 이하가 되고 1초가 흘렀을 때
    3. 나가기 조건: 시작 버튼을 눌러 메뉴를 호출한 후 나가기를 선택했을 때
    4. 라운드가 종료되면 지금까지 진행한 결과를 반영한다. (아이템, 골드, 클리어 여부에 해당)
  • 라운드 진행 규칙
    1. 보스전 이라고 간주되면 보스의 체력과 이름을 반드시 공개한다.
    2. 적이 남아있는 동안은 진행 시간이 특정 시점에서 멈출 수 있다. (일부 라운드는 예외)
    3. 일반적인 특징이 없다면 기준 시간은 180초로 한다. 이 규칙은 권장이며 강제하진 않습니다.

5. 무기의 표준

  • 무기 사용 규칙
    1. 무기는 서로 다른 종류 4개를 선택해야 합니다.
    2. 무기마다 공격 방식은 개별적으로 처리합니다.
    3. 사용자의 무기는 자동으로 발사합니다.
    4. 무기 교체 버튼 (기본 A)를 누르면 무기 종류를 바꿀 수 있습니다.
    5. 필드에서 5번째 슬롯을 선택하면 무기를 사용하지 않는 것으로 간주합니다.
  • 표준 밸런스 배울 표 및 규칙
    1. spalsh: 0.5 (0.4 ~ 0.5), 1개체가 적을 여러 개 타격 할 수 있는 경우
    2. chase: 1.0, 모든 발사체가 적을 추적하는 경우 (추적에 실패하여도 이 배율을 적용)
    3. shot-reflect: 1.04 ~ 1.08, 1개체가 벽을 반사하는 경우
    4. shot-front: 1.6, 1개체는 반드시 전방을 향해 나아감
    5. shot-Xway: 1.2 ~ 1.6, 1개체는 전방 어떤 방향이든 날라감 (수직 방향 포함)
    6. shot-back: +0.4, 1개체가 후방에 날라가는 경우 해당 배율을 추가로 더함 (수직 방향 제외)
    7. mixed: 각 무기 형태의 비율을 독립적으로 곱하여 근사치 추정
  • 밸런스 타입 정의 기준
    1. splash 해당 무기의 모든 개체가 splash 공격이어야 한다. 다른 타입과 혼합 불가
    2. chase 모든 발사체가 적을 추적하는 경우. 추적에 실패해도 적용
    3. shot 모든 발사체가 단일 형태의 shot 서브타입 종류를 가진 경우
    4. mixed 발사체의 타입이 섞인 경우 (단 splash는 제외)
  • 무기 리스트
    1. 멀티샷: 1.33 = (front 2/6 + chase 2/6 + 2way) = (0.333 * 1.6) + (0.333) + (0.333 * 1.4)
    2. 미사일: 0.5 = splash
    3. 애로우: 1.04 = shot-reflect
    4. 레이저: 1.2 = (front 2/4 + chase 2/4) = (1.4 * 0.5) + (1.0 * 0.5)
    5. 사피아: 1.0 = chase
    6. 파라포: 0.48 = spalsh v2
    7. 블래스터: 1.52 = 2way front
    8. 사이드웨이브: 1.46 = (3way front + 2way back) = (0.6 * 1.3) + (0.4 * 1.7)
    9. 링: 1.8 = 8way (360 degree divide 8 -> 5way front, 3way back 으로 해석) = (0.625 * 1.5) + (0.375 * 1.9) = 1.7975 -> 1.8로 간주
    10. 래피드: 1.6 = front
    11. 선단일: 1.0 = chase
    12. 부메랑: 1.55 = shot - special movement (임의 지정됨)
    13. 칼날: 1.0 = chase
    14. 코그휠: 1.7 = front - penetration
    15. 연사이: 1.8 = (50% front + 50% back) = (0.5 * 1.6) + (0.5 * 2)
    16. 사방탄: 0.5 = splash
    17. 타워핑크: 1.0 = chase
    18. 타워퍼플: 1.04 = shot-reflect
    19. 헬전: 1.3 = (50% front + 50% chase) = (0.5 * 1.6) + (0.5 * 1.0)

6. 스킬의 표준

  • 스킬 기본 규칙
    1. 스킬의 쿨타임은 20초, 24초, 28초 입니다.
    2. 스킬의 dps는 (쿨타임 × 배율 × 0.21)로 결정합니다.
    3. 스킬은 A슬롯 4종류, B슬롯 4종류로 총 8종류를 사용할 수 있습니다.
    4. 같은 슬롯 번호 끼리 쿨타임을 공유하므로, 동시에 사용할 수 있는 스킬 수는 4개입니다.
  • 쿨타임 규칙
    1. splash, area 타입은 최소 24초의 쿨타임이 지정됩니다.
    2. 나머지는 쿨타임의 제약이 없습니다.
  • 타입 배율 표준 규칙
    1. chase: 1.0, 모든 개체는 적을 추적함. (추적 실패 여부 무시)
    2. splash: 0.4 ~ 0.5, 모든 개체 및 타격은 스플래시 공격을 함. 예외 없음.
    3. shot-front: 1.2, 모든 개체가 전방 방향으로 나아갈 때
    4. shot-Xway: 1.02 ~ 1.2, 샷의 방향이 여러 방향일 때, 이 범위 이내 적용
    5. area-splash: 0.3 ~ 0.6, 특정 영역 내의 적 전부를 타격할 때 (영역이 넓을 수록 배율 감소)
    6. area-attack: 0.7 ~ 1.2, 특정 영역 내의 적을 전부 타격하지만 그 최대 수의 제약이 강한 경우
    7. formula: 1.0 ~ 1.2, 무기 자체가 임의 공식을 쓰는 경우 (최대 1.2배 이상을 초과할 수 없음)
    8. 28초 쿨타임을 가진 스킬은 +0.1배율을 보너스로 추가합니다.
  • 타입 세부 설정 규칙
    1. splash 모든 발사체로 인한 타격이 스플래시 형태일 때 적용한다. (타격 수 범위: 최소 20 ~ 최대 50)
    2. area-splash 특정 영역을 지정하여 여러 개체에게 공격을 수행할 때 적용한다. (타격 수 범위: 최소 12 ~ 최대 50)
    3. area-attack 특정 영역을 지정하여 공격하지만 개체 수 제한이 강함 (타격 수 범위: 2 ~ 6)
    4. chase 스플래시가 아니며 모든 개체가 적을 추적하믄 경우 지정됨
    5. shot-xway chase, splash, area가 아니고 shot-front가 아닌 경우 적용합니다.
    6. formula: 아예 다른 무언가인 경우 (shot 방식도 아니란 뜻)

7. 필드의 표준

  • 모든 필드 개체는 FieldData를 상속받아야 한다. (Round는 필드 개체가 아닙니다.)
  • 필드 개체에 접근하려면 process, display 함수로만 접근해야 한다.
    단, 필드에서 주입이 필요한 요소는 제외한다.
  • FieldData를 상속 받은 다른 파일 끼리 순환 참조를 하는 것은 금지된다.
  • FieldData의 공통 속성 또는 함수로 참조하는 것은 허용되나, 자제하는 것을 권장.
  • Enemy, Round, Weapon, Sprite등은 표준 함수를 제외한 서로의 함수를 모른다고 가정한다.
  • Round에서 Player를 조작할 수 밖에 없다면 Player에 대한 직접 참조를 허용한다.
  • 상속 관계
    1. 제일 낮은 층은 FieldData이다. 어떠한 필드 객체도 재참조 하지 않는다.
    2. 그 다음 층은 Enemy, Round, Weapon, Player 이다. 이들은 서로를 참조하진 않는다.
    3. 그 다음 층은 FieldState, FieldSystem 입니다.
    4. 필드는 메인 시스템을 참고할 수 없습니다.
    5. 필드는 유저 시스템을 참고할 수 있습니다.

    • 여기서부터는 틀 복사용으로 남겨둔 것임 1. 목적과 범위

    이 문서는 표준을 작성하는 방법을 정의한다.

    • 순서가 필요 없는 항목은 ul + li
    • 순서가 필요하면 ol + li
    강조하고 싶은 주의사항은 이런 박스로 표시한다.
